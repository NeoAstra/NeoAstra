# Migrating Step 2 RPC to v2 capabilities

Step 3 intentionally changes Step 2's registration-only model to fail-closed authorization.

1. **Inventory operations.** Assign every `[NeoRpcMethod]` and `[NeoRpcEvent]` one stable colon-separated `Permission`, for example `[NeoRpcMethod("open", Permission = "documents:open")]`. Generated builds report `NEORPC015` for missing or malformed IDs. Manual `AddCommand`/`AddEvent` registrations must also provide `NeoRpcCommandOptions.Permission`/`NeoRpcEventOptions.Permission`.
2. **Create a catalog.** Add explicit `NeoPermissionDeclaration` entries mapping each permission to its exact generated command/event names, version, risk, scope family, platform support, timeout, concurrency, redaction, and documentation. Register plugin catalogs explicitly; do not copy plugin permission sets into application grants without review.
3. **Write the v1 capability file.** Select immutable application view IDs, target platforms, optional authenticated origins, and only the required permissions/scopes. Do not encode user-specific paths in committed files; use reviewed build configuration or opaque application location tokens where appropriate.
4. **Resolve in build/CI.** Run `NeoAstra.Capabilities.Tool` once per target platform in Release, run twice for determinism, review the canonical output/hash, and reject any validation error. Linux cannot use origin selectors.
5. **Configure the host.** Set `NeoRpcOptions.AuthorizationService` to `NeoCapabilityAuthorizationService` and `CapabilityManifest` to the same resolved manifest. Keep the production profile and explicit abuse limits. The old behavior with no service now denies every renderer call.
6. **Provide trusted metadata.** Create `NeoRpcSessionIdentity` in native/application lifecycle code with stable view/session IDs and platform. Pass authenticated top-level source origin from native message metadata when supported. Never pass payload identity or the current browser URL. On Linux set `WholeViewTrust` only for a view that never loads untrusted content.
7. **Move resource checks into typed scopes.** Replace arbitrary string paths/URLs/commands with exact typed argument fields expected by the selected scope family. Keep OS no-follow/final-handle checks and redirect/byte checks in the native resource implementation.
8. **Test denial first.** Test no authorization service, unknown permission, wrong view/platform/origin, missing origin, subframe, Linux untrusted view, spoofed identity fields, malformed/out-of-scope arguments, cancellation/disposal, and all rate/concurrency/resource limits. Verify diagnostics contain codes/counts but no arguments, URLs, paths, tokens, or bodies.

Development local-server mode is now explicit: `SecurityProfile = DevelopmentLocalApp`, `Release = false`, and a loopback HTTP `DevelopmentOrigin`. Release mode rejects it and detailed renderer errors. There is no compatibility switch that restores implicit grants; trusted backend-only applications needing a temporary bridge should implement an explicit, narrowly scoped `INeoRpcAuthorizationService`, document it as development-only, and remove it before release.
