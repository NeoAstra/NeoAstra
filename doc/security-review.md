# Security and resource-limit review

This review covers the implemented ABI 1.8 behavior relevant to specification sections 19, 34–35, and 38. Browser content, navigated origins, resource request data, and native provider output are untrusted. Application configuration and application-supplied event/resource callbacks are trusted, but failures at those callback boundaries must remain contained.

The RPC and capability layer adds fail-closed authorization above bridge admission. Every renderer operation requires one permission; immutable resolved policy checks backend-owned view/session/platform/main-frame/origin/whole-view metadata and typed scopes before dispatch. Registration and plugin discovery grant nothing. Strict release resolution, token-bucket rate and synchronized concurrency/resource limits, cancellation/session closure, redacted errors, and bounded snapshots address policy broadening, flooding, races, and leakage. Exact scope policy is restricted to the build review artifact. See [capabilities and security](capabilities-and-security.md) and the [threat model](security-threat-model.md) for test evidence, OS-handle/redirect responsibilities, and platform limitations.

## Verified controls

- **C and callback boundaries.** Public C arguments use sized/versioned structures, pointer/count pairing, UTF-8 validation, enum/range checks, UI-thread checks, and explicit ownership. Callback slots contain exceptions and wait for active calls when cleared. Resource-provider and release callbacks are exception-contained. WebView2, WKWebView, and WebKitGTK message ingress now contain C++, Objective-C, and backend failures rather than allowing them to unwind through a browser callback.
- **Bridge trust and limits.** `NeoBridgePolicy.Disabled` is the default and denies both directions of web/native messaging. `TrustedOrigins` requires a non-empty `BridgeOrigins` collection and accepts messages only when the backend-authenticated source exactly matches an entry. Marking a custom scheme as an application scheme does not grant bridge access. `TrustEntireView` is a separate explicit opt-in that permits messaging for any script capable of reaching the view's handler; it cannot be combined with an origin list, and an empty list never means allow-all. User-info origins are rejected. Accepted JSON payloads are limited by `MaximumMessageSize` (1 MiB by default), and ingress is dropped after view teardown begins.
- **Default-deny decisions and external URIs.** Permissions, TLS errors, popups, file selection, downloads, and other sensitive decisions use deny/cancel defaults where specified. A URI reaches the OS external opener only after the application explicitly resolves a new-window decision with `OpenExternal`; NeoAstra does not automatically launch unknown schemes.
- **Queue and timeout limits.** The native dispatcher rejects additions at `MaximumPendingDispatches` (65,536 by default), and managed zero limits are rejected. Deferred decisions have a positive timeout capped at ten minutes and resolve through their backend-specific safe default.
- **Custom resources.** Scheme names cannot replace built-in schemes; registrations must be unique and have valid origins and providers. Request/provider/response callbacks are contained. Buffered request bodies and byte responses are capped at 64 MiB; larger responses must be file-backed. Request/response headers are capped at 1 MiB and URI/method/origin/response metadata at 32 KiB. Native responses require coherent body pointer/kind/length fields, known declared byte lengths that match the actual byte count, valid single-line metadata/header syntax, and absolute file paths. A response release callback runs at most once.
- **Directory paths.** `NeoDirectoryResourceProvider` fixes an absolute root, normalizes and bounds candidates to that root, rejects encoded separators/dot traversal and nulls, permits only `GET`/`HEAD`, and rejects symbolic links/reparse points by default. Response header values reject line breaks/nulls, and directory responses set `nosniff`.
- **Disposal quiescence.** View teardown marks the native object destroyed, abandons pending decisions, clears and quiesces callbacks, and then disconnects backend handlers. Managed shutdown cancels accepted dispatcher waits that have not started and drains native completions before freeing callback roots.

## Backend and residual limitations

- Browser engines materialize or serialize a web message before NeoAstra can apply `MaximumMessageSize`; the limit prevents delivery/allocation in application callbacks, not the engine's initial temporary allocation.
- WebKitGTK 4.1 does not report a trustworthy script-message source origin. Consequently `TrustedOrigins` is rejected on Linux. `TrustEntireView` is supported there, but received messages report `SourceOrigin == null` and the implementation never substitutes the current top-level URI as proof of sender identity. WebKitGTK also lacks custom-resource initiator/frame/kind metadata and several authority/per-origin/service-worker controls reported by the capability API.
- WebView2 does not currently expose custom-resource request bodies through this adapter. WKWebView and WebKitGTK enforce the 64 MiB request limit; WebView2 reports an empty body.
- File-backed responses are intentionally not size-capped or copied. Their paths are trusted application/provider output after absolute-path validation. The directory provider checks links before the backend opens the file, so an attacker able to mutate the asset tree concurrently may still create a check/open race; keep the asset root non-writable by untrusted principals.
- Backend-reported origins and browser security semantics remain platform inputs. Origin matching is exact (scheme/host/port after backend normalization) but does not replace normal web protections such as CSP, CORS, and least-privilege bridge handlers.
- `TrustEntireView` deliberately removes origin authorization. Remote top-level navigation, remote or compromised iframes, remotely hosted scripts, mutable local assets, HTML/script injection, and an ineffective CSP can all gain the application's bridge authority. Use it only for a locked-down local view whose complete content and navigation surface are controlled; treat every bridge handler as exposed to every script/frame the engine permits to call the registered handler.
- Native callers can still choose very large nonzero message/queue limits. Those are trusted-host policy knobs; applications should retain defaults unless a measured workload requires otherwise.

## WebKitGTK implementation comparison

The local Wry implementation registers a `WebKitUserContentManager` script-message handler and receives the message payload without trustworthy sender-origin provenance. The local Tauri implementation adds separate initialization/invoke keys and IPC request/protocol validation; those controls form a capability and request-validation layer rather than recovering an authenticated WebKitGTK sender origin. NeoAstra therefore models whole-view trust explicitly instead of presenting the current page URI as verified message provenance.
